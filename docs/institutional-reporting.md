# Institutional Export & Reporting (STEP 39)

Institutional reporting in FacultyLens is **evidence + aggregation + traceability + controlled export**. A report is an
artifact for authorized academic review; it never changes grades, assessments, CO/PO mappings or approvals, never ranks
faculty or diagnoses students, and never makes accreditation claims.

## Flow

```
Report Configuration → Preview (validate access, count records) → Generate → Export (PDF/CSV/XLSX) → Download → Audit
```

## Report registry

`config/institutional_reports.php` is the single registry. Each type declares its label, description, allowed scopes,
whether it is built from student data, and its builder class.

| Key | Reuses | Scopes |

| `ASSESSMENT` | STEP 13/18/37/38 | ASSESSMENT, ASSESSMENT_VERSION |

## Authorization and scope (server-side only)

`App\Services\ReportAuthorizationService::resolve()` turns a request into a `ReportContext` — the **only** data boundary
builders may query within:

| Scope | Who | Resolution |
|---|---|---|
| `FACULTY` | everyone | `CourseAccessService::accessibleCourses` (owned + active collaborations) |
| `COURSE`, `ASSESSMENT`, `ASSESSMENT_VERSION` | course members (`view`) | the selected course; assessment must belong to the course, version to the assessment |
| `DEPARTMENT` | `department_roles` (ADMIN) | courses owned by users of that department |
| `INSTITUTION` | `institution_roles` (ADMIN) | all courses (optionally one program) |

Student-data reports also require `view_student_data` (OWNER/EDITOR or admin) on the courses in scope; otherwise the
request is rejected with **403 “You are not authorized to generate this report.”** Filter validation errors return
**422** with safe messages (“The selected assessment version is unavailable.”, “No data available for the selected
filters.”). Nothing is ever `SELECT *`-ed and filtered in React.

## Data contract

Every builder (`App\Services\Reports\*ReportBuilder`) returns the same structure, and the formatters render it:

```json
{ "metadata": {}, "summary": [], "sections": [], "tables": [], "warnings": [], "record_count": 0 }
```

- `metadata` — FacultyLens, report type, generated by/at, `data_as_of`, scope, filters, course, assessment, assessment
  version, academic year, semester, data period, privacy note.
- `tables[]` — `{key, title, columns[{key,label}], rows[], note}`; CSV/XLSX are produced from this structured data, never
  from rendered HTML.

**PDF** reuses the STEP 18 DomPDF infrastructure (`resources/views/reports/institutional-pdf.blade.php`: title, metadata,
summary KPIs, sections, tables, page numbers, footer). Tables longer than `pdf_row_limit` are truncated with a note
recommending CSV/XLSX. **CSV** is UTF-8 with a `metric,value` summary block followed by one block per table
(`# <Table title>` marker + header row). **XLSX** is written by the dependency-free `XlsxWriter` with a `Summary` sheet
plus one sheet per table present in the report.

## Lifecycle, storage and expiration

`institutional_reports` stores the request (`report_type`, `scope_type`, `course_id`, `assessment_id`,
`assessment_version_id`, `department`, `program_id`, `filters` snapshot, `format`), the status
(`PENDING → PROCESSING → COMPLETED | FAILED | CANCELLED`), the private `file_path`/`file_name`/`file_size`,
`record_count`, a stored `summary`, `data_as_of`, `generated_at`, `expires_at`, `file_deleted_at` and a safe
`error_message` (never SQL, paths or stack traces).

- Small reports are generated synchronously; `DEPARTMENT`/`INSTITUTION` scopes and reports above
  `async_threshold_records` are queued via `GenerateInstitutionalReportJob` (works with the database queue worker,
  Redis or Horizon). No database transaction is held during generation.
- Files live on the private `local` disk under `institutional-reports/{user}/{uuid}.{ext}` and are streamed only by
  `GET /api/reports/{report}/download` after `InstitutionalReportPolicy::download` (creator or admin). Expired files return
  **410**.
- `php artisan reports:purge-expired` (scheduled daily 02:30) deletes expired files, sets `file_deleted_at` and keeps the
  record and audit rows.

## Version traceability

A report for `v3.0` stores `assessment_version_id`, is built from the version’s question snapshot
(`assessment_version_questions`) and uses the analysis attached to that version — or the current analysis whose analyzed
content hash equals the version snapshot (STEP 38 “CURRENT”). It is never reinterpreted using `v4.0`, and a generated
file never changes; regenerating produces a new report.

## Privacy

Institutional reporting defaults to aggregates: average, median, min, max, counts, percentages, distributions. Student
names, identifiers, e-mails and individual answers are never exported. Student-data reports carry a privacy footer and
are audited on download. `INSUFFICIENT_DATA` stays labelled as such (never a gap), PO sections say “not configured”
when no program is mapped, unevaluated AI metrics read “Not evaluated”, and wording is “CO/LO coverage evidence” — not
“accreditation compliance”.

## Audit events

`REPORT_PREVIEWED`, `REPORT_REQUESTED`, `REPORT_GENERATION_STARTED`, `REPORT_GENERATION_COMPLETED`,
`REPORT_GENERATION_FAILED`, `REPORT_DOWNLOADED`, `REPORT_DELETED` — each with user, report id, type, scope and filter
metadata (never student answers).

## API

```
GET    /api/reports/types                 report types/scopes/formats for the current user
GET    /api/reports/filters               access-scoped filter options (+ applicable keys for type/scope)
GET    /api/reports                       my reports (paginated, status/type filters)
POST   /api/reports/preview               validate + build + return summary and truncated tables
POST   /api/reports                       create (201 sync, 202 queued)
GET    /api/reports/{report}
GET    /api/reports/{report}/download     authenticated private stream (audited)
DELETE /api/reports/{report}
```

## Frontend

- `/reports` — **My Reports** (Report · Scope · Format · Status · Generated · Expires · View / Download / Delete), polls
  while reports are generating.
- `/reports/create` — builder: Report Type → Scope → applicable Filters (course → assessment → version cascade) → Format →
  **Preview Report** → **Generate Report**. Unauthorized configurations show the access notice; empty datasets block
  generation.
- `/reports/:reportId` — status (polled), file details, metadata, stored summary, download, regenerate, delete.
