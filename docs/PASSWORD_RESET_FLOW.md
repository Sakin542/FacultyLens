# FacultyLens Password Reset Flow

```
Faculty
  ↓  /forgot-password (React)                       POST /api/auth/forgot-password {email}
Laravel Password Broker (Password::broker()->sendResetLink)
  ↓  creates a random 64-char token, stores bcrypt(token) in password_reset_tokens (60-min expiry, 60-s throttle)
User::sendPasswordResetNotification($token)
  ↓  EmailService::sendPasswordReset() → email_deliveries row (type PASSWORD_RESET)
SendFacultyLensEmailJob  →  queue "emails"  →  Redis  →  Horizon (supervisor-emails)
  ↓  FacultyLensMail('reset-password')  →  Gmail SMTP
Faculty inbox: “FacultyLens — Reset Your Password”
  ↓  link  FRONTEND_URL/reset-password?token=<token>&email=<email>
/reset-password (React) — token + e-mail read from the URL, new password + confirmation entered
  ↓  POST /api/auth/reset-password {token, email, password, password_confirmation}
Password::broker()->reset()  →  token verified (Hash::check) + not expired  →  Hash::make(new password)
  ↓  token row deleted (single use) · remember_token rotated · all API tokens deleted · PasswordReset event
  ↓  audit PASSWORD_RESET_COMPLETED · SECURITY_ALERT notification + e-mail “Your password was reset”
“Password reset successfully.” → Go to Login → sign in with the new password
```

The user is **not** signed in automatically after a reset.

## Endpoints

| Method | Path | Throttle | Response |
|---|---|---|---|
| `POST` | `/api/auth/forgot-password` `{email}` | `password-reset` (5/min per IP, 20/h per IP, 6/h per address) | Always `200 {status: success, message: "If an account exists for this email address, a password reset link has been sent."}` |
| `POST` | `/api/auth/reset-password` `{token,email,password,password_confirmation}` | `password-reset` | `200` success · `422 {code: INVALID_RESET_TOKEN}` for invalid / expired / reused token or unknown e-mail · `422` validation errors for the password fields |

Password policy: at least 8 characters with letters and numbers (`Password::min(8)->letters()->numbers()`), confirmed.

## Token security

* Generated by Laravel's `DatabaseTokenRepository` (`Str::random(64)` seeded with the app key), stored **hashed**
  (bcrypt) in `password_reset_tokens`; the plaintext exists only in the queued job payload and the e-mail link.
* Expires after `auth.passwords.users.expire` = 60 minutes; the broker refuses to create a new token within
  `throttle` = 60 seconds (the API still answers with the generic message).
* Single use: the row is deleted on successful reset; a reused link yields `INVALID_RESET_TOKEN`.
* Never logged: `EmailLogSanitizer` masks `token=` query values; audit rows record only the outcome and e-mail domain;
  `email_deliveries` stores metadata only; API responses never echo the token or password.
* The reset URL is built from `FRONTEND_URL` only — the client cannot supply a redirect target.

## Account-enumeration protection

* Identical body and status for known, unknown and throttled addresses.
* For unknown addresses the controller performs a dummy `Hash::make()` so response time matches the token-hashing
  path.
* Rate limits apply per IP and per address regardless of account existence; the 429 body is generic.
* The reset endpoint returns the same `INVALID_RESET_TOKEN` message for a bad token, an expired token, a token for a
  different account and an unknown account.

## E-mail content (`resources/views/emails/reset-password.blade.php`)

Subject `FacultyLens — Reset Your Password`. States that a reset was requested, shows the **Reset Password** CTA with
a copyable link, the expiry in minutes, *If you did not request a password reset, you can safely ignore this email.*
and *For your security, never share this reset link with anyone.* No account details, no current password.

Password-reset e-mails bypass notification preferences and the regular per-user e-mail ceiling (they count against
the separate security ceiling of 20/h) and are never deduplicated across requests.

## Audit events

`PASSWORD_RESET_REQUESTED` (outcome LINK_SENT / THROTTLED / UNKNOWN_ACCOUNT), `PASSWORD_RESET_COMPLETED`,
`PASSWORD_RESET_FAILED` (outcome INVALID_TOKEN / UNKNOWN_ACCOUNT). Metadata: outcome + e-mail domain only.

## Frontend

* `pages/ForgotPassword.tsx` — validation, loading state, generic success (never echoes the address), 429 and
  network errors without internals.
* `pages/ResetPassword.tsx` — reads `token`/`email` from the query string; states *form → submitting → success*
  and *invalid* (missing link parts, server `INVALID_RESET_TOKEN`) with **Request a New Link**; client-side policy
  mirror; server field errors mapped onto inputs; show/hide password; keyboard operable.
* Route `/reset-password` (public, `PublicLayout`).

transport so it can never send to Gmail by accident.

## Troubleshooting

| Symptom | Cause |
|---|---|
| Generic message but no e-mail | Address not registered (by design) · broker throttle (wait 60 s) · Horizon not running · `MAIL_MAILER=log` |
| Link opens the wrong host | `FRONTEND_URL` |
| `INVALID_RESET_TOKEN` immediately | Link older than 60 min · already used · e-mail in URL edited · `APP_KEY` changed since the token was issued |
| 429 on forgot-password | 5 requests/min per IP or 6/h per address exceeded |

## Production deployment

`FRONTEND_URL=https://<public host>`, `MAIL_MAILER=smtp` with the Gmail App Password on the server only, Horizon
running (`docker-compose.prod.yml → horizon`), `EMAIL_TEST_ENDPOINT_ENABLED=false`, `EMAIL_PREVIEW_ENABLED=false`.
Consider lowering `auth.passwords.users.expire` if institutional policy requires shorter links.
