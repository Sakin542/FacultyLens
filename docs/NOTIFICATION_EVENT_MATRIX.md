# FacultyLens Notification Event Matrix (STEP 47)

Authorization rule abbreviations refer to abilities in `backend/config/collaboration.php`; "members(x)" = course owner + ACTIVE collaborators whose role holds ability *x*. "actor" = the faculty member who performed the action. All notifications are queued through `StoreNotificationJob` on the default queue (database in dev, Redis in production). Status legend: **LIVE** = producer wired and covered by `NotificationIntegrationTest`; **SUPPORTED** = type, event and listener exist, no producer in this deployment.

## Explicitly *not* notified
* Automatic archival of the previously finalized version during `finalizeVersion()` (`automatic=true`) — the finalization notification already says so.
* Draft edits (`ASSESSMENT_VERSION_UPDATED`), comment edits/resolutions, document processing, embeddings, AI evaluation runs — technical or self-evident events that would only add noise.
* Anything about individual students: names, identifiers, marks, ranks or answer text never leave the performance/grading services.
